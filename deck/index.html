What this talk is about

2. Current work: GSM + Agentic Engineering

Using agents as bounded engineering collaborators.

From dashboards to pipelines

  • Reports should be generated.
  • Outputs should be testable.
  • Changes should be reviewed through GitHub.
  • Examples should deploy automatically for inspection.

Agentic Engineering

A workflow where humans set direction and agents execute bounded engineering loops with auditable evidence.

  1. Define requirement.
  2. Implement.
  3. Test and demo.
  4. Open PR.
  5. Review and iterate.

What agents are already good at

  • Scaffolding examples and documentation.
  • Refactoring repeated package patterns.
  • Creating requirement matrices.
  • Deploying reviewable demos.
  • Summarizing PR/check status.

Where agents still fail

  • Vague requirements become shallow spikes.
  • UI functionality can look complete but miss behavior.
  • Status updates can imply progress without evidence.
  • Human feedback needs a structured path back into the work.

Requirements are the contract

  • Functional specs.
  • Data specs.
  • Regression tests.
  • Baseline examples.
  • Known gaps.

Human feedback loop

Telegram questions → recommendations → decisions → project docs → implementation

The interview framework keeps ambiguity out of GitHub-only dead ends.

The agent workspace

  • Memory: durable project context.
  • Skills: repeatable workflows.
  • Heartbeats: periodic checks.
  • Dreams: private synthesis and questions.
  • Project pages: public status and demos.
