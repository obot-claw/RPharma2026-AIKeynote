R/Pharma 2026 Keynote Draft

Agentic AI for Clinical Trial Operations

What the open-source community can do next

Jeremy Wildfire

The thesis

Agentic AI can streamline clinical trial work when it is grounded in open, inspectable, reusable clinical software workflows.

Focus: faster study data analysis across setup, conduct, closeout, and submission to FDA and other regulators.

Why R/Pharma?

  • This community already works in the pre-competitive open-source space.
  • Clinical trial operations have shared problems hiding behind company-specific implementations.
  • Agentic AI gives us a new way to build, maintain, and validate shared infrastructure.

Three parts

  1. How open source entered the clinical trial pipeline.
  2. What SafetyGraphics and GSM taught us about shared monitoring frameworks.
  3. How the workflow is shifting from code assist to agentic engineering.

~10 minutes

1. A quick history

From company-specific SAS macro libraries to open clinical frameworks.

The old model

  • Every company had its own large repository of SAS macros.
  • Clinical reporting infrastructure was powerful, but mostly internal.
  • Teams repeatedly solved similar operational and analysis problems in parallel.

The hybrid era

  • SAS remains central in many organizations.
  • R, Python, and other open-source tools become part of the clinical trial pipeline.
  • Teams begin connecting closed-source macro libraries with open-source workflows.

Open frameworks + local customization

Shared core
community-maintained methods, examples, and docs
Company extensions
local standards, templates, and review practices
Clinical use
study setup, conduct, closeout, and submission support

Pharmaverse-style approaches show the direction: shared infrastructure does not eliminate company-specific needs; it gives them a better base.

Open source changed the surface area

More of the clinical workflow became visible, reusable, and improvable.

~12 minutes

2. SafetyGraphics and GSM

Two open-source projects, one recurring pattern: pre-competitive clinical monitoring frameworks.

SafetyGraphics

  • Focused on safety monitoring.
  • Reusable safety review displays.
  • Interactive workflows aligned with common clinical questions.
Core lesson

When data inputs, displays, examples, and docs are open, safety review assumptions become easier to inspect.

GSM

  • Focused on RBQM and statistical monitoring.
  • Broader study monitoring and quality workflows.
  • Reusable outputs that can be generated, reviewed, and versioned.
Core lesson

Monitoring workflows should be treated like software: specified, tested, documented, and improved over time.

The shared pattern

Pre-competitive
common problems before company-specific customization
Open
public repos, examples, and documentation
Inspectable
visible assumptions and reviewable outputs
Reusable
frameworks that can carry many studies

Why this matters for AI

  • Agents need explicit workflows, artifacts, and quality bars.
  • Open-source projects already expose those artifacts.
  • Clinical operations work becomes something agents can help draft, test, document, and improve.

Once the workflow is open and software-shaped...

AI can do more than autocomplete code.

Current and future workflows for clinical trial operations.

What changed in the last few years

  • LLMs became more capable and more available.
  • The workflow moved beyond isolated code suggestions.
  • Agents can now execute bounded loops across requirements, code, docs, tests, demos, and pull requests.

Agentic engineering

Humans set direction; agents execute bounded work loops with auditable evidence.

Requirement → implementation → checks → demo → PR → review

Clinical trial operations opportunities

  • Setup: prepare analysis workflows, examples, specifications, and study configuration.
  • Conduct: monitor data, refresh outputs, triage anomalies, and maintain review artifacts.
  • Closeout: reconcile outputs, document decisions, and assemble evidence.
  • Submission: support traceable packages for FDA and other regulatory authorities.

What agents can help with now

  • Drafting requirements and requirement matrices.
  • Scaffolding open-source package work.
  • Updating documentation and examples.
  • Running static and rendered-output checks.
  • Summarizing evidence for human review.

What still needs humans

  • Scientific and clinical judgment.
  • Regulatory accountability.
  • Risk acceptance and prioritization.
  • Approval boundaries for external actions.
  • Final interpretation of study data.

obot as the demo thread

  • A dedicated open-source development agent.
  • GitHub as the engineering surface.
  • Browser QA for rendered outputs.
  • Memory and skills for continuity.
  • Telegram feedback loops for decisions and review.
